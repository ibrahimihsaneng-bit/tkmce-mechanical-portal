# MECH TKMCE — Unified Focus Studio & Resource Manager
## Master implementation prompt for Antigravity

**Existing site:** https://mechtkmce.vercel.app/  
**Programme:** TKM College of Engineering, B.Tech Mechanical Engineering, Autonomous 2024.  
**Objective:** Extend the existing portal with an original Regain-inspired focus system and an intuitive academic resource publishing pipeline. Preserve the current site, content, URLs and navigation. This package is a specification and UI reference, not a production implementation.

## 1. Execution rules
Act as a senior product designer, full-stack engineer, Android engineer, browser-extension engineer, education specialist, security engineer and QA lead. Inspect the actual repository, framework, hosting, content model, authentication, Android source and Focus Studio before editing. Inventory valid resources and routes, capture baseline screenshots, establish a development branch and rollback point. Do not rebuild unrelated sections, replace valid notes with demo content, or add a second focus dashboard. The supplied HTML screens and PNGs are original design references; adapt them to the real app and replace illustrative content with real data. Use the existing framework unless a measured benefit justifies a change. Implement, test and document incrementally. Do not deploy production changes before owner approval.

## 2. One entry point — existing Focus Studio only
Keep the existing main navigation and add no new top-level links for blockers, timers, insights, device pairing, rooms or schedules. The existing **Focus Studio** entry is the single entry point. Inside it use progressive disclosure: Overview / Protection / Schedule / History, with connected devices and optional study rooms inside a secondary More or settings panel. Default Overview presents one primary action, Start session. The full-screen reader is a child state of Focus Studio, not another product. On mobile use a small local tab strip or accessible sheet, not a second competing global navigation. Maintain deep links for accessibility and recovery, and a visible back-to-portal action. Existing Learn and Exam pages may launch a prefilled session through the same Focus Studio. Resource Manager is separate from the student focus area and accessible through the existing authorised admin/contributor entry; never make upload controls part of the immersive reader.

## 3. Design references and implementation
Read design/README.md and open design/index.html. Follow the screenshots in design/previews. Use a refined, original forest/cream design for focus, retaining existing portal branding elsewhere. Primary #16594D, deep #142D28, text #172F29, paper #F5F5EF, surface #FFFFFF, muted #64766E, border #DDE5DD. Use high-contrast dark mode, 4/8px spacing, comfortable 14–16px controls, 16–20px body text for reading, generous whitespace, 12–16px radii, restrained shadows, simple icons, reduced motion and tabular timer digits. Do not copy Regain branding, artwork, mascot or proprietary code. Avoid noisy graphs, badges, streak pressure and clutter. Every screen has one clear next action; advanced options collapsed by default; use plain-language inline labels, contextual help and meaningful empty/error/loading states. Mobile 320px and up, keyboard navigation, visible focus, screen reader names, WCAG 2.2 AA target. Do not use fake functionality or decorative controls in the actual implementation.

## 4. Focus session flow
Overview → choose existing semester / subject / module / topic or Paper Mode → enter one goal → pick duration and optional protection profile → optional prepare checklist → start. Provide a one-click Quick Start with sensible defaults. Presets: 10/2, 25/5, 50/10, 90/15 minutes, configurable exam duration, 45/10 paper mode, stopwatch and custom; all adjustable. Optional Pomodoro rounds, short/long breaks, sound off by default, notifications opt-in, hide timer, extend, pause/resume, reset with confirmation, finish, skip break, safe exit. Use persisted session IDs, deadlines and accumulated active duration; handle sleep, page refresh, tab suspension, device clock changes and recovery; never double-record completion. Record actual elapsed active time and distinguish paused time. Do not force immediate next session. Save reading position, goal and selected resource. Paper mode requires no continuous screen interaction. Offer voluntary checklist for silencing notifications, closing tabs, keeping phone away and preparing notebook. Do not require phone to use laptop.

## 5. Immersive learning
Open actual notes, PDFs, formulas, diagrams and PYQs in the existing Focus Studio reader. Hide global navigation and recommendations, retain only essential reading controls, goal, compact timer, pause/finish, accessible exit, bookmark and optional distraction parking lot. Support warm paper, clean white, sage, blueprint, dark and pure black themes; adjustable font, line spacing, reader width, zoom, optional fullscreen and wake lock when supported. No flashing/continuous animation. Preserve all reference images, captions, formula rendering and source attribution. Parking lot captures thoughts locally and optionally converts selected thoughts into planner tasks after a session. On return from a hidden tab, offer a nonjudgmental reminder and restore position. Never treat every tab switch as misconduct.

## 6. Protection — actual platform capability
Inside Protection present plain-language status cards: Web focus, Desktop browser extension, Android companion. The normal website cannot block unrelated tabs, native apps or remotely lock a phone. Distinguish unavailable, not installed, not authorised, ready, active, degraded and expired. A status must come from actual capability/acknowledgement, never a mock toggle. Offer Gentle (quiet reader), Deep (supported chosen restrictions) and Strict (voluntary commitment with advance disclosure and optional ordinary-exit reflection). Always retain immediate emergency access, accessibility, normal uninstall/permission revocation, critical apps and safe expiry. No anti-uninstall, hidden surveillance, admin bypass, irreversible lock or remote unlock dependency. Users can stop protection on their own device. The student controls each rule. Explain the limits at the point of action, not through a long onboarding lecture.

## 7. Desktop extension and browser filtering
If authorised, create a companion Manifest V3 Chrome/Edge extension, linked only from Focus Studio Protection. Use supported declarativeNetRequest, alarms, storage and scoped messaging/host permissions. Allow user-selected domains, exact host/subdomain matching, optional paths, academic allowlist and exceptions; schedules and per-site active-use budgets where measurable. Add a neutral intervention page with goal, time left, return to study, save for later, end safely and emergency access. Keep local rule state with session ID and expiry; clear stale rules on start/restart, permission loss and expiration; document alarm delays and offline behavior. Never claim the extension can block native apps or other browsers. For supported web Shorts/Reels feeds, use narrowly scoped content scripts/rules, no private message capture, no credentials, no breaking required player controls. Treat third-party UI changes as compatibility failures and degrade visibly. Review current extension store policies before release. No broad history collection.

## 8. Android companion and digital wellbeing
Preserve existing APK and signing arrangements. Inspect native source; if none, report blocker and provide a separate development companion only with approval. Consider Kotlin/Compose, local Room/DataStore, UsageStatsManager with user-granted usage access, appropriate supported scheduling APIs and tightly scoped user-requested accessibility interventions only if justified, permitted and tested. Select installed apps through permitted package visibility; restrict chosen apps temporarily, by recurring schedule or daily usage budget where feasible. Essential exceptions include emergency calls/alerts, accessibility tools, authentication, medical, navigation, academic PDF/calculator/note apps and user-selected communication. Show clear permission disclosures, revocation and status. Feature-specific Reels, Shorts, Spotlight filtering is experimental/version-dependent: no private text capture, raw event histories or fake enforcement. Disable broken integrations safely. Offer OS-native Digital Wellbeing/Do Not Disturb guidance as fallback. Android force-stop, reboot, OEM battery management, permission revocation and offline expiry must be tested; no guarantee of OS-wide enforcement or store approval. iOS is optional future work requiring supported Screen Time APIs/entitlements, not a web feature.

## 9. Educational video mode
Inside Learn and Focus Studio provide topic-linked, curated educational videos, source/channel, duration, objective and relevant notes. Use permitted official embeds, no own infinite recommendation feeds or autoplay; preserve required player controls/ads, do not redistribute videos, provide external link when embedding unavailable. Academic allowlists can include institutional and open course resources; verify links and let users edit. A website-only guided resource list is not a system blocker.

## 10. Schedule, budget, history and optional rooms
Inside Focus Studio allow time/day/subject/module/goal/profile recurring schedules, weekday/weekend rules, daily distraction budgets and near-limit opt-in reminders. Use actual authorised measurements, distinguish website focus time, extension browser activity and Android device usage, no double counting overlapping sessions. Show weekly/monthly history, completed goals, practice accuracy, and optional private reflection; do not diagnose addiction, infer mastery from reading time or display fake metrics. Handle missed schedules, timezone changes, device restart, offline and disabled permissions. Optional private code-based silent study rooms after core functionality is validated; no public social feed, leaderboard, forced streak or shared private screen-time data. Completion shows actual active time, goal done/partial, optional reflection, saved distractions and break/exit.

## 11. Optional connected devices
Keep device management inside Protection. Pair own devices using authenticated, short-lived, one-time codes/QR, explicit consent on each device, capability handshake and revocation. Synchronise only session ID, goal, duration, profile reference and authorised state. Use HTTPS, scoped authentication, replay protection, expiry, audit events without private content. Every device independently enforces its own authorised profile and local expiration; no server required to unlock. Never allow covert control of another person's phone. Show acknowledgements and connection failures accurately; don't show Protected until actual enforcement is confirmed. Web-first/local-only mode must remain functional without paid APIs or mandatory accounts.

## 12. Resource Manager — a guided, structured uploader
One authorised Resource Manager entry, accessible from existing admin menu; use existing auth and role system or implement server-enforced roles (student read, contributor draft, reviewer approve, admin manage). A contributor may submit drafts but cannot publish unless granted rights. Default interface: destination picker (scheme → semester → verified course → module/experiment → optional topic), resource type, drag/drop file or ZIP / authorised external link, preview, validation and publish/submit. Cascade options from official curriculum, disable unavailable descendants, retain choices while editing, offer clear back/edit. For course-level resources or labs use appropriate structure; do not force five modules. Auto-suggest title and course code based on filename, never silently guess destination. Display breadcrumb and filename before submission. Offer batch upload, per-file mapping, upload progress, retry, cancel, draft recovery and actionable errors. Keep required fields minimal, auto-fill metadata where safe, use expandable advanced fields. Duplicate detection via SHA-256 and canonical resource ID; explicitly offer keep existing, new revision or cancel. Never overwrite silently. Preview PDF/images/text safely, show file size, destination, source and licence, visible approval status. Publication must be transactional: stage → validate → review → commit metadata and asset references → invalidate cache/index → verify destination. Keep immutable revisions and rollback. No destructive migration of existing resources.

## 13. Supported resources and content rights
Accept only approved formats and configurable size limits: PDF, Markdown/plain text, sanitised HTML, JSON manifest, PNG/JPEG/WebP, sanitised SVG, approved external video/reference URL, ZIP containing manifest and assets. Do not execute uploaded code or embed arbitrary active HTML. Validate server-side actual MIME/signatures, file count, total expanded size, path traversal, symlinks, nested archive limits and compression bombs; quarantine/scan as available, reject executable/unknown types. Use private staging storage and authorised signed upload URLs if needed; server controls final keys. CSRF protection where relevant, rate limits, strict CORS, authorisation on every write and preview, sanitisation and CSP. For remote imports do not server-fetch arbitrary private URLs: allow approved hosts or safe constrained retrieval with DNS/IP/redirect checks. Never expose keys or trust client-side role flags. Respect Vercel request/body/runtime limits; use suitable durable object storage, not ephemeral server filesystem. Do not add paid dependencies without approval. If backend credentials missing, mark uploader preview-only and report exact integration steps.

## 14. Academic hierarchy and notes standards
Use verified TKMCE Autonomous 2024 official curriculum, not generic KTU. S3–S8 reference: https://tkmce.ac.in/uploads/syllabus/B.Tech%20Mech%20S3-S8%20syllabus%20%282024%20scheme%29.pdf ; locate separate official S1/S2 sources. Prioritise S1–S5, then S6–S8; preserve all prior notes and ZIP packages. Scheme → semester → course code → module/experiment → topic → resource. Support electives and labs correctly. Produce complete beginner-friendly textbook explanations, derivations, examples, checked numericals with SI units, questions, short revision notes, formula sheets, flashcards and references. Distinguish authentic PYQs, faculty material and AI-assisted practice. Use verified assessment patterns only; never fabricate course codes, topics, dates or completeness. For academic images, NO AI-generated images or AI-redrawn diagrams: obtain relevant real source images, verify accuracy and reuse licence, store permitted assets locally and display directly within notes with caption, alt text, creator, source URL and licence. If rights unavailable, link to original and mark image pending. No fabricated links or copied textbook chapters. Verify all topic coverage and integrate search, bookmarks, focus sessions and explicit offline downloads. No demo content in production.

## 15. Data and manifest
Use templates/resource-manifest.example.json as an illustrative format, and templates/resource-manifest.schema.json as a proposed validation contract (adapt to actual repository, validate academic IDs against catalogue separately). Each resource has stable id, scheme, semester, courseCode, module/experiment destination, optional topic, type, title, status, source, licence, files (relative paths + checksums), version, timestamps and provenance. ZIP import: manifest at root, resource files under files/; optional images referenced by relative paths with per-image licensing; validate manifest and file inventory before extraction/publishing. A file name cannot override manifest destination without review. Support simple upload without manifest; server creates one. Store revision history, uploader/reviewer IDs privately, content status and audit trail. Public view only displays published resources with attribution; indexing only published content. See docs/RESOURCE_WORKFLOW.md.

## 16. Accessibility, performance and privacy
Core content remains free and ad-free; no mandatory student login for basic reading and timers. Local-first preferences, history and planner; opt-in sync and deletion controls. Data minimisation, no hidden tracking. WCAG 2.2 AA target, accessible dialogs, keyboard and screen reader testing, no horizontal overflow on 320–1920px, reduced motion. Lazy-load notes/PDFs/images and companion functionality; target LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 where measured. Preserve existing offline/APK functionality; explicit cache/download indicators, cache versioning and storage controls. Do not claim offline access until tested.
