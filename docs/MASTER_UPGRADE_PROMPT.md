# Master upgrade prompt — MECH TKMCE

Act as a senior frontend engineer, mechanical engineering educator and academic content editor. Upgrade https://mechtkmce.vercel.app/ using this package as a non-destructive reference and content seed. Audience: only TKMCE B.Tech Mechanical Engineering students, especially beginners; 2024 autonomous scheme. Do not create a general marketplace, paid coaching or unrelated branch libraries. Keep required common courses assigned to ME students. Keep free access, existing PYQs, faculty notes, syllabus viewer, APK, search and existing URLs. Identify the actual repository framework and data model before changing anything. Do not assume Next.js or overwrite the existing site with the demo. Make a feature branch, backup existing content and compare routes before/after.

## Phase 1 — source and curriculum audit
Read the college PDF and portal PDF linked in content/sources.json. Check edition, course codes, semester, optional baskets, each module and assessment pattern against the original pages. Reconcile discrepancies with newer college releases and flag them for human review. The starter catalog is an inventory of course slots, not an exhaustive elective or topic extraction. Import electives only once the student chooses the applicable basket. Link original PDFs, do not republish third-party textbooks or unlicensed figures. Mark draft versus faculty-reviewed content visibly. Do not label the portal official without authorization.

## Phase 2 — beginner learning interface
Build a responsive accessible reading experience: Start from zero, semester S1–S8, subject/course code, module, lesson. Provide search (titles, codes, topics and body), clear previous/next navigation, bookmarks/progress stored locally, print-friendly layout, keyboard navigation, high contrast and font-size controls. Default to simple English. Use a restrained navy/teal palette, white reading surface, readable typography and minimal animation. No account required for basic content; no ads or paywall. Preserve offline APK functions; verify cache/versioning separately. Never use placeholders labelled completed. Show actual coverage counts. Treat all content as untrusted data; render escaped text or sanitized Markdown, no arbitrary HTML scripts. Keep API keys server-side.

## Phase 3 — academic content generation pipeline
Create a source register with URL, PDF page, date accessed, license and provenance. Build syllabus topic IDs and course-specific assessment metadata. Generate one original long-form lesson per topic from verified academic references: prerequisites, everyday analogy, definition, physical mechanism, diagrams, derivation with assumptions, SI units, solved examples increasing in difficulty, common mistakes, practice with answers and references. Use the five draft chapters as structural seeds, not as finished textbook notes. Prefer original SVG engineering diagrams with text alternatives; never scrape random Google images. Keep quoted material within license/permission limits. Do not claim to have read a source when only its title was retrieved. For labs use approved procedures, safety warnings and sample data clearly labelled synthetic. Review every equation, sign convention, units, arithmetic, and diagram. Require faculty approval before setting status=reviewed. Maintain version history, coverage matrix and source links; refuse to publish if required source or checks missing. Produce HTML/Markdown plus print/PDF and optional DOCX from the same source of truth. Use per-module and per-semester packages rather than duplicating manually. Do not apply 60-mark format to 40-mark or CIA-only subjects; match verified course-specific rules.

## Phase 4 — GATE foundation for ME students
Make GATE optional and secondary to TKMCE curriculum. Map only relevant lessons to the current official ME syllabus; keep exam-year version and verify official source before stating coverage or patterns. Include prerequisite math, conceptual MCQ, MSQ, numerical answer practice, feedback and gradual difficulty. Clearly label original questions versus authenticated PYQs. Never invent year tags. No guaranteed scores or exam predictions. Start from zero with units, algebra, free-body diagrams, stress, fluid and thermal concepts.

## Phase 5 — integration and release
Import the data in content/catalog.json and content/lessons.json after reviewing the schema; use the demo as a UX reference. Maintain existing URL redirects and download links, add schema validation and unit tests, run accessibility and mobile checks, verify every source link, print output, image alt text, search, empty states, local progress and offline behavior. Test on staging before production. Never silently delete any existing materials. Release only reviewed modules as complete; draft previews can be explicitly enabled. Deliver a changed-file summary, test results, known gaps, coverage report and rollback steps. If repository access is unavailable, return a merge plan and patch rather than claiming deployment.
